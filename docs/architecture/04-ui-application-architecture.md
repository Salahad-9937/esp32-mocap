# 4. Архитектура эталонного графического приложения {#sec-ui-application-architecture}

## 4.1. Архитектурная роль Composition Root (`src/`)

Каталог `src/` представляет собой **исполняемый корень сборки (Composition Root)** всего проекта на стороне ПК:

* Модули каталога `src/` связывают воедино headless-библиотеку `mocap-core`, оконную графическую подсистему и пользовательский интерфейс в единое законченное бинарное приложение (`mocap-app`).
* Приложение является эталонным образцом интеграции библиотеки `mocap-core`, демонстрируя разработчикам корректный жизненный цикл инициализации потоков, опроса каналов, проведения калибровки и маршрутизации пространственной позы.

### Модульная структура каталога `src/`:
```text
src/
├── main.rs                 ── Точка входа: парсинг CLI, запуск оконной подсистемы
├── app.rs                  ── Центральное состояние сессии UI, жизненный цикл кадров
├── config.rs               ── Сохранение пользовательских настроек окна и путей к профилям
├── state.rs                ── Потокобезопасные буферы телеметрии и контекст сессии
├── views/                  ── Изолированные графические панели интерфейса
│   ├── connection.rs       ── Управление подключением к COM-порту и индикация канала связи
│   ├── topology.rs         ── Интерактивная матрица оборудования шины I2C
│   ├── inspector.rs        ── Многоканальный осциллограф сырых сигналов
│   ├── mapper.rs           ── Визуальный конфигуратор привязки датчиков к модели тела
│   └── calibration.rs      ── Пошаговый мастер статической калибровки гироскопов
└── visuals/                ── Схематичный трехмерный вьюпорт
    ├── viewport.rs         ── Интерактивная 3D-камера с орбитальным вращением
    ├── skeleton.rs         ── Проволочная отрисовка звеньев тела и сочленений
    └── axes.rs             ── Отрисовка ортогональных координатных базисов датчиков
```

## 4.2. Модель многопоточности и изоляция горячего контура

Для предотвращения зависания пользовательского интерфейса и пропуска кадров входящего радиоканала приложение разделяет выполнение на два изолированных асинхронных контура:

1. **Фоновый поток приема данных (Ingestion Thread):**
   * Выполняет блокирующее или квазиблокирующее чтение виртуального последовательного порта Bluetooth через драйвер библиотеки `mocap-core`.
   * Работает с частотой поступления кадров ($60 \dots 80$ Гц), производит распаковку бинарных пакетов, проверяет CRC и прогоняет измерения через активный конвейер фильтрации.
   * Записывает последние полученные измерения в неблокирующий потокобезопасный кольцевой буфер (Ring Buffer / Triple Buffer) с минимальным временем удержания блокировки.
2. **Главный графический поток UI (Rendering / GUI Thread):**
   * Управляется оконным циклом событий (Event Loop) с частотой обновления монитора ($60 \dots 144$ Гц).
   * На каждом кадре отрисовки считывает мгновенный срез данных из кольцевого буфера фонового потока.
   * Производит построение интерфейсных виджетов, обновление осциллографов и отрисовку 3D-вьюпорта без задержек сетевого ввода-вывода.

## 4.3. Функциональные панели пользовательского интерфейса (`views`)

Интерфейс приложения декомпозирован на независимые функциональные экраны:

### 4.3.1. Панель подключения и связи (`views::connection`)
* Автоматическое сканирование доступных в операционной системе последовательных портов (Bluetooth RFCOMM и USB-UART).
* Кнопки подключения, отключения и паузы потока.
* Диагностическая телеметрия в реальном времени:
  * Фактическая частота принимаемых кадров в секунду (Hz).
  * Общее количество принятых пакетов с момента старта сессии.
  * Счетчик выпавших кадров (по разрывам 16-битного счетчика пакетов).
  * Счетчик отброшенных поврежденных кадров (CRC Errors).

### 4.3.2. Матрица топологии оборудования (`views::topology`)
* Графическая сетка из 8 строк (мультиплексоры с адресами `0x70`..`0x77`) по 8 столбцов (подканалы 0..7).
* Цветовая индикация состояния каждой ячейки матрицы по результатам автосканирования:
  * Зеленый: датчик физически обнаружен, возвращает валидный `CHIP_ID 0xD1` и активно передает данные.
  * Серый: подканал пуст (датчик не подключен).
  * Красный: мультиплексор найден, но опрос подканала вызывает ошибку шины I2C.

### 4.3.3. Осциллограф и инспектор сигналов (`views::inspector`)
* Выбор любого активного датчика для детального анализа.
* Вывод числовых физических значений линейных ускорений ($Ax, Ay, Az$) и угловых скоростей ($Gx, Gy, Gz$).
* Скользящие динамические графики сигналов за последние $3 \dots 5$ секунд. Позволяют оператору мгновенно оценить уровень механических вибраций, шум покоя и правильность ориентации осей датчика при движении.

### 4.3.4. Визуальный конфигуратор привязки (`views::mapper`)
* Предоставляет интерактивный рабочий процесс связывания аппаратных каналов со скелетом:
  1. Оператор шевелит конкретной конечностью (например, правой рукой).
  2. В окне конфигуратора подсвечивается канал, на котором регистрируются пиковые угловые скорости.
  3. Оператор кликает на соответствующую кость в списке анатомических сегментов, связывая физический узел с моделью.
  4. Созданная конфигурация сохраняется в локальный профиль формата TOML.

### 4.3.5. Мастер пошаговой калибровки (`views::calibration`)
* Пошаговый сценарий устранения аппаратного дрейфа нуля:
  * Шаг 1: Инструкция оператору зафиксировать тело неподвижно (стоя или сидя).
  * Шаг 2: Нажатие кнопки запуска калибровки. Приложение собирает 200 калибровочных кадров, отображая прогресс-бар.
  * Шаг 3: Автоматический расчет статических смещений нуля гироскопа $\vec{b}_g$ и дисперсии шума.
  * Шаг 4: При успешной проверке на неподвижность поправки фиксируются в рабочем профиле сессии, и система переходит в режим боевого трекинга.

## 4.4. Схематичный проволочный 3D-визуализатор (`visuals`)

В приложении присутствует минималистичный трехмерный вьюпорт, предназначенный для визуальной валидации позы без тяжелого графического рендеринга:

* **Орбитальная 3D-камера:** Поддержка вращения вокруг центра модели, масштабирования колесом мыши и панорамирования.
* **Схематичный каркас скелета:** Отрезки линий, соединяющие сочленения в единое анатомическое дерево. Длины звеньев настраиваются или берутся из эталонных пропорций.
* **Локальные ортогональные базисы (Axes Gizmos):** Отображение взаимно перпендикулярных цветных осей ($X$ — красный, $Y$ — зеленый, $Z$ — синий) в точке расположения каждого активного датчика. Базисы вращаются в реальном времени строго по кватернионам, выдаваемым модулем Sensor Fusion.
* **Сетка пола:** Горизонтальная координатная сетка, служащая пространственным ориентиром горизонта.
